## Ключевые решения, влияющие на следующий шаг

- **Группировка — по файловой локальности, не по категориям отчёта.** Находки одного файла закрываются подряд, чтобы файл читался в контекст один раз. Показательный случай — `ProgramDetailModal.tsx` (1662 строки): его 7 находок разнесены так, что группа 5 читает только диапазон 96-330, а группа 7 работает по точным координатам (63-73, 128, 264) без чтения файла целиком.
- **Размер группы — 2-4 находки**, чтобы при исчерпании лимита посреди работы потери были минимальны. Единственное исключение — документационные находки, поэтому они разбиты на 11a/11b.
- **Порядок внутри групп задан там, где экономит работу:** TEST-1 перед LOG-1 и TEST-2 перед LOG-2 (тест даёт красный для фикса), CONV-1 перед LOG-8 (сначала вынести `CartItemRow`, потом править один файл), CRIT-2 перед DEAD-2 (обе меняют `PlannerViewProps`). DOC-4 (числа тестов) и TEST-4 (coverage config) — в самом конце: их значения меняет каждая предыдущая группа.
- **Правило одной находки = одного коммита** (`CLAUDE.md` → «Проработка отчётов аудита») сохраняется внутри групп; группа — это единица сессии, а не коммита.
- **CONV-2 не должна втянуть Трекер в i18n:** `TrackerView` не подключён к `useTranslation` (переведены только `TabBar`, `AppHeader`, `SettingsModal`), поэтому фикс — вынести строку из доменного слоя в UI, а не переводить весь компонент.
- Пункт в `ROADMAP.md` не снимать, пока не закрыты все 39 находок — даже при прерывании на середине.
